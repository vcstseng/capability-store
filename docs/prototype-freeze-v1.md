# Capability Store prototype v1 — 凍結紀錄

日期：2026-11-05（Asia/Taipei）

## 本輪決定與範圍

使用者決定不修改既有 Sales L3 的搭配能力區，要求用同一方式完成其餘九個企業領域後凍結。本輪新增 54 筆雙語能力說明，合計 60 個；共用同一個動態模板。Sales 六筆內容逐位元與原 e3388db 版本一致，沒有改寫既有 L1／L2／L3 UI 或新建協作流程。

這是概念展示，並非可執行工具、服務或已驗證方案。60 個能力都保留 concept_only／implementation=null；所有例子都是虛構編寫，未執行。企業情境以一般人看得懂的任務為主，清楚說明輸入、產出與人工確認。權限與停止條件是設計要求，不是已實作的保護機制。

## 凍結內容

- 十個企業領域、30 個工作環節、60 個能力構想與 60 個中英文 L3。
- 每個 L3：情境、輸入→處理→產出、虛構例子、人工判斷／資料與權限／停止條件、可搭配能力，以及適當的參考或明確留空。
- 沿用既有 GitHub 候選作閱讀線索，17 個能力各附一個有限範圍的參考。沒有即時查核、安裝或執行第三方資源。其他 43 個能力不硬配 repo；領域層級參考仍在 L2。
- 原始快照、候選池與來源 catalog 32 主題／84 資源不改；AI 資源入口與 Trending 保存快照保留。
- 99 Problems、Startup Radar、Consulting Agents 的整體整合未實作；沒有逐題 matching、搜尋、登入或能力執行。

## 資料與重現

L2 與能力基本欄位：data/processed/concepts/business-concepts.json。

L3 增補：sales-details.json（原六筆）及 business-details.json（新增五十四筆），均以穩定 idea-* ID 連接。build 合併成 concepts.json，拒絕重複 ID、缺少能力詳情、缺翻譯、無來源參考或斷裂搭配連結。不需要為每個能力建立一份 HTML。

凍結輸入雜湊：config/freezes/prototype-v1.json。凍結以 Git tag capability-store-prototype-v1 定位；tag 建立與公開部署結果記在本檔末尾。網站內容、UI 與建置輸入納入雜湊，進度／部署紀錄不納入，避免自我引用。

## 驗證

- 20 項 Node 測試全數通過；建置通過。
- 原來源驗證通過：32／84、92 個來源引用、14 份 raw 檔案雜湊核對。
- 瀏覽器：十個 L2 均有六個詳情入口；60 頁中文桌面（1280px）及 60 頁英文手機（375px）逐頁載入。每頁六個內容區，無橫向溢出，未見 console error。
- 前一輪已驗證語言切換、重整、返回位置與能力互連；本輪沿用相同 UI。
- 財務／採購／營運／管理例子的算式與合計已回讀核對。需求、出貨、成本、收入、同意與權限等企業口徑不混為一談。法律與人事示例不作真實案件判定。
- 詳細 UI 紀錄：reviews/prototype-v1-browser-qa.json。畫面：screenshots/prototype-v1-finance.jpg。

## 目錄清理

使用者另要求凍結前清理目錄；已移除 18 個無需要檔案與 5 個空目錄。原始證據、可重現腳本與有用歷史留存，詳見 [目錄與清理紀錄](file-directory.md)。不把本機仍使用的 dist 當作垃圾移除。

## Freeze 之後

本版內容與 UI 完成後停止，不自動增加能力、刷新來源、重分類或接入自動執行。後續整合 demo 可引用此版本的能力 ID；任何實質修改需有使用者新指示並建立下一版。Freeze 不代表能力已實作、資料即時或 GitHub 適用性已驗證。
